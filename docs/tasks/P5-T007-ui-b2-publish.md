# UI 改版為 B 版（三）：B2 發布面板

## 目標
D-013。發布從右側滑出；最上面寫「發到哪裡」，列出還沒處理的，選「公開」要勾「我知道」。

## 範圍
### 包含
- 發到哪裡（類型 → target）、還沒處理的（可跳回）、分類／標籤、封面、發布方式、外部副作用警告
- 「核准並發布」：打開面板時主區切到成品，看過（PREVIEWED）才准核准，核准綁畫面上那一份的 hash
### 不包含
- 排程（後端沒有）、摘要（後端沒有欄位）

## 中斷／接手紀錄
- 最後完成：全部
- 已通過驗證：`npm run verify`；CDP 實測（示範資料）：草稿一路走到「已送到」、選公開後沒勾「我知道」
  按鈕不能按、缺封面時擋下並說明原因、還有建議時只提醒不擋；真實後端：建稿→打開發布面板→自動渲染、
  推進 PREVIEWED、按鈕可按（**沒有按下去**：那會在正式站建立草稿，留給使用者決定）
- 下一步：無
- Blocker：無

## 完成結果

- 新的發布抽屜：發到哪裡（契約 `JobTarget.postType`，additive）、還沒處理的（可跳回建議或圖片）、
  分類／標籤、封面、存成草稿／馬上公開（公開要勾「我知道」）、一顆「核准並…」
- 打開面板：主區切到成品；還沒渲染就先渲染；校樣重載後才推進 PREVIEWED，才准按
- 核准 hash 與畫面上校樣的 ETag 對不上就不給按，提供「重新整理成品」
- 刪掉舊的核准卡片與發布卡片
- 示範資料的假後端補上「載入校樣＝看過」的規則，阻擋原因的文字改成跟後端一致

**跟以前不一樣的地方（要讓使用者知道）：**
- 還有未處理的建議時，以前的發布卡片會擋住發布（它把所有 blocker 都當禁令），規格卻寫
  「提醒不是禁令」。現在照規格：列出來、可以跳回去看，但不擋。這就是待裁定的 Q-1。

**已知殘餘：**
- 前端靠比對後端的中文字串判斷哪些 blocker 是自己會處理的；後端改字，前端會把它當成硬性阻擋
  （多擋不少擋）。長久解法是後端回結構化代碼。
