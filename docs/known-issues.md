  標記檔壞掉（不是合法 JSON）時當成有過資料庫：資料庫不在就停止啟動，要照訊息處理；
  工作目錄與媒體檔的實體路徑是在使用前檢查的，檢查完到真正使用之間被換成符號連結的情況不擋（本機單人工具，能這樣改檔的人本來就能直接讀資料目錄）；
  候選圖檔案不見了（含路徑不合格、檔案不存在）回 400「檔案不見了」，不是以前的 404（路由不在本 Task 範圍）；
  `generated-images/`、`drafts/` 裡面的符號連結一律不認（使用者自己放的捷徑也一樣）；整個資料目錄或 `generated-images/`、`drafts/` 本身換成符號連結、指到不跟其他存放位置重疊的地方，仍然可用；
  標記檔的 `databaseCreated` 只在套完 migration 後補記，資料目錄不可寫時補記失敗只警告，那段期間資料庫不見仍照全新處理；
  DB 裡的媒體路徑若是別處的舊絕對路徑（P8-T003 之前存的、不在資料目錄、也對應不到 `generated-images/` 裡的檔），現在一律當成不見了，不再照原路徑讀刪；
  `generated-images/` 裡的符號連結，刪媒體時不刪（連結檔留著，不影響使用）；
  實際位置的比對靠作業系統回報的真正拼法，大小寫混用的回歸測試只在不分大小寫的檔案系統上跑（其他環境自動略過）。
