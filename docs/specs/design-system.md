# 設計系統

> 擁有範圍：顏色、字體、版面、品質底線、文案。
> 程式：`src/ui/styles.css`（變數在最上面）、`src/ui/components/`。
> 版面依 D-013 的 B 版（文件式），設計稿 https://claude.ai/artifact/1D5TrmCQESR3icmD6TVnC6 。

## 定位

不是儀表板，是**一張正在改的稿紙**。文章放在中間像一張紙，修改建議標在字上，
右邊的卡片一對一對應。介面是暖灰的桌面，文章是紙白——軟體的東西與文章的東西永遠分得開。

## 顏色

只有一個強調色（墨綠），只給「下一步該按的那一顆」。建議用四種分類色，底色標在字上、
前景色寫在標籤上；決定與警示另有一組。所有色值都是 `styles.css` 最上面的變數，深色模式
在 `prefers-color-scheme: dark` 裡換一組，變數名不變。

| 變數 | 用途 |
| --- | --- |
| `--shell-bg`／`--shell-panel`／`--shell-sunken`／`--shell-line` | 桌面、面板、凹下去的底、分隔線 |
| `--shell-text`／`--shell-text-dim` | 主要與次要文字 |
| `--proof-*` | 紙（校樣永遠是淺色） |
| `--accent`／`--accent-strong`／`--accent-soft`／`--on-accent` | 唯一的強調色 |
| `--kind-typo`／`-fact`／`-source`／`-style`（各有 `-bg`） | 建議分類：錯字、事實、出處、寫法 |
| `--mark`／`--seal`／`--warn`／`--danger`（及 `-on-shell`） | 改動符號、已核准、警示、危險 |
| `--proof-dim`／`--proof-sunken` | 紙上的次要文字、紙上凹下去的底（對照收起來的那一行） |
| `--diff-del`／`--diff-add`（各有 `-bg`） | 對照裡刪掉的字（紅、刪除線）與加上的字（綠、底線）。印在紙上，深色模式不換 |

校樣 iframe 裡的標記顏色寫在 `ProofView.tsx` 的 `HIGHLIGHT_COLORS`（iframe 讀不到外層的
CSS 變數），改分類色時兩邊要一起改。

## 字體

介面與正文用黑體；大標題（頁面標題、抽屜標題、品牌）用宋體給一點書卷氣。宋體是中文字體，
不會有「西文字體套不上中文、兩套字體打架」的問題——舊規則禁止的是那個。
數字、hash、版本號用等寬字。

```css
--font-cjk:   'PingFang TC', 'Noto Sans TC', 'Microsoft JhengHei', system-ui, sans-serif;
--font-serif: 'Songti TC', 'Noto Serif TC', 'PMingLiU', serif;
--font-num:   'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, monospace;
```

只用系統內建字體，不從網路載入（本機工具，離線也要能用）。

校樣區的正文字級要**貼近正式站的實際觀感**（段落預設 `medium`），不要用介面的
小字級去顯示文章。

## 版面

三個畫面：

| 畫面 | 內容 |
| --- | --- |
| **B0 稿件總覽** | 「新長文／新日記」、拖放或 ⌘V 開新稿、類型篩選；每篇一句狀態加一顆「打開」 |
| **新稿件**（D-030，P5-T029） | `#/new`。只問類型與標題（日記有「用今天」），沒有內文框；底下一句「建立之後直接在文章上寫，粗體、連結、標題的工具列就在上面。」按「建立並打開」→ 進 B1 **直接在打字模式**，游標在內文開頭。從總覽拖放檔案或 ⌘V 貼上進來時，原稿帶著走（「已帶入貼上的原稿，N 字。建立後在文章上繼續改。」），建好照舊轉成段落、不進打字模式 |
| **B1 工作區** | 頂列：返回、類型、標題、「請 AI 看一遍」、「發布…」（沒有檢視切換，D-018）。中間是文章，右欄是建議卡片與圖片區 |
| **B2 發布面板** | 從右邊滑出：發到哪裡・作者、還沒處理的、分類、封面、怎麼發，最後一顆「核准並…」。作者（P5-T024）：「作者：某某」一行，設好預設就什麼都不用點；還沒設預設時名單直接攤開，點名字＋「設為預設」；「改」只改這一篇（標「只有這一篇」）；帳號只能用自己時不給選、警示寫要去 WordPress 升成 Editor；預設作者不在這個站時寫「還沒選」並擋住發布按鈕；讀不到作者清單而有預設作者時也擋住並講原因；完成畫面寫出作者（沒送時寫「作者是發布台的帳號（名字）」） |
| **設定精靈**（P8-T002） | `#/setup`。四步：連線 WordPress → AI 編輯 → 發到哪裡 → 完成。沒有設定時打開發布台自動進來 |

```
┌────────────────────────────────────────────────────────────────────┐
│ ←  日記  20260828                    [✦ 請 AI 看一遍|▾]  [發布… 4] │
├───────────────────────────────────────────────┬────────────────────┤
│  r2  5c02f7ab    對照上一版 標題與網址 改原文 │ 全部4 錯字1 寫法2… │
│  ┌────────────── 紙 ──────────────┐          │ ┌ 錯字・錯字 ─────┐ │
│  │ 今天讀完這本書，▒想到很多事▒。  │  ←─→    │ │ 想到很多事 → …  │ │
│  │ …                              │          │ │ [接受][自己改]  │ │
│  └────────────────────────────────┘          │ └─────────────────┘ │
│                                               │ ▸ 圖片              │
└───────────────────────────────────────────────┴────────────────────┘
```

- **任何動作都跟著內容走**，不需要知道「現在是第幾步」。舊版的左狀態軌與步驟卡片已拿掉。
- **抽屜而不是換頁**：標題與網址、發布都從右邊滑出，文章一直留在左邊看得到（D-008）。
- **正文直接在文章上改**（P5-T010）：「改原文」與卡片上的「自己改／去原文改」都讓校樣變成可打字，
  看到的是排好版的文章，不露任何標籤；卡片進來的游標停在那一項引用的字前面，那段字用螢光筆黃標出
  （找不到字就標整段，P5-T011；連段落都定位不到的，游標放文章開頭、頂端講「文章裡找不到「…」」，P5-T017），
  沒有段落、正文找不到而**標題**裡有那段字的（講標題的建議），游標與標色放在標題、焦點給標題，打字直接進標題（P5-T031，`lib/edit-target.ts`），
  顏色刻意跟四種建議標記都不同。編輯中工具列換成
  「取消／儲存」、紙張加一圈框，右欄與上方動作鎖住（避免編到一半內容被換掉）。
  - **標題也在文章上改**（D-030，P5-T029）：編輯中外框裡的標題變成可點（細虛線框，點進去是實線藍框），
    `contenteditable="plaintext-only"`：只收純文字，貼上一律插純文字、換行攤平成空格；Enter 跳到正文開頭；
    格式快捷鍵在標題裡不做事。按「儲存」時標題與正文**一起存成同一個新版本**（只送有改的那一邊）。
    進入編輯時與存檔時的標題只差在空白（連續空格、NBSP、tab、前後空白）不算改，不建新版本；真的改了送使用者打的原樣。
    長度上限照該篇模板（`JobTemplate.titleMaxLength`）。標題清空按儲存：不送，校樣上方紅字「沒存成功：標題不能是空的」（日記加「日記的慣例是 YYYYMMDD，例如 20260928」），留在編輯中。
    「取消」連標題一起還原。「標題與網址」抽屜照舊可用，兩邊讀寫同一個 `title`；抽屜裡的標題清空也不給存（同一條規則，`contract/plain-title.ts`）。
  - **空的正文**（新稿件剛建好）：編輯中正文放一個空段落，前面淡灰色提示「從這裡開始寫…」（打了字就消失）。
    沒在編輯時，上方工具列那顆「改原文」寫「開始寫」；頂列「請 AI 看一遍」反灰（滑過去：「正文是空的，先寫點內容再請 AI 看」），
    旁邊一句灰字「先寫點內容，才能請 AI 看、發布」。發布面板「還沒處理的」列出「正文是空的，先寫點內容再發布」，核准按鈕反灰。
    「建議網址」與「在這裡插圖」照常（看的是標題／使用者自己的描述）。
- **校樣不自己捲動**（P5-T029）：滑鼠停在文章上滾一次，外層就捲。做法見 `ProofView.tsx` 檔頭「二」：iframe `scrolling="no"`、
  外層用 CSSOM 把文件 `html` 設 `overflow: hidden`、body 設 `display: flow-root`（包住 alignleft／alignright 浮動圖）、高度量到 body 下外距與 html 下內距為止，
  內容比 iframe 高（scrollHeight 大於 clientHeight）時用 scrollHeight，不裁內容；打字時瀏覽器把文件捲下去的，量測時捲回頂端。
  新稿件「直接進打字模式」只對建立後第一次打開生效：離開那一篇（回總覽、上一頁、換篇）或載入失敗就作廢。
- **格式工具列**（D-028，P5-T028）：編輯中校樣工具列下面多一排按鈕，分四組——連結、粗體、斜體｜H2、H3、內文｜
  項目清單、編號清單、引用｜分隔線。**出現哪些照該篇模板的 `allowedTags`**（`JobDetail.template.allowedTags`，
  規則在 `src/ui/lib/rich-format.ts`，有測試），不是寫死。按鈕反映游標所在的格式（`aria-pressed`，強調色淡底）；
  瀏覽器會做壞的組合直接停用：清單裡的 H2／H3（Chrome 會產生 `<h2><ul>`，要先按「內文」離開清單）、
  標題裡的粗體。再按一次同一個標題＝回到內文；清單裡按「內文」＝離開清單；引用裡按「引用」＝拿掉引用。
  分隔線插在游標那一整塊的**後面**，不切斷段落。快捷鍵 ⌘B／⌘I／⌘K（非 Mac 用 Ctrl）；⌘U 攔下來不做事
  （底線不在 allowlist）。按鈕在 mousedown 就擋預設動作，焦點與選取留在 iframe。
  - **連結輸入框**在工具列下方展開（不用 `window.prompt`）：Enter 套用、Esc 取消；只打網域自動補 `https://`；
    收模板 `allowedSchemes` 的網址，以及站內的 `/路徑` 與 `#錨點`（規則見 security.md「連結網址規則」）；
    其他（含 `javascript:`、`../post`、`//host`）紅字講「只接受 https、http、mailto 開頭的網址，或站內的 /路徑、#錨點」。
    游標在既有連結裡時顯示原網址，按鈕變「更新」並多一顆「移除連結」。沒選字就插入以網址為字的連結。
  - **貼上**保留 allowlist 內的格式（粗體、斜體、連結、標題、清單、引用、分隔線），樣式、class、span、font、
    script、圖片、表格外框、不允許的連結一律拿掉、字留著；h1→h2、h4 以下→h3；只有純文字的剪貼簿照舊插純文字。
    拖檔案進正文會被擋掉（插圖走「在這裡插圖」）。只有行內內容的片段插在游標處、前後空白保留（`<span> brave </span>` 貼進
    `Hello|world` 是 `Hello brave world`），只拿掉原始碼排版的頭尾換行；貼多段時每段頭尾修剪、段內空白保留。
    樣式照 CSS 規則解析（屬性名完全相符，`mso-bidi-font-weight` 不算 `font-weight`；後面覆蓋前面、`!important` 優先）。
  - **存檔**時只整理**改過或新增的頂層區塊**，沒碰過的逐字保留（跟進入編輯時逐塊做序列比對；插入、刪除段落
    不會讓後面的區塊都算改過）。整理（`contract/rich-text.ts`，規則同後端）：`b`／`i`→`strong`／`em`，Chrome 的 `<p><ul>`、
    `ul` 直接包 `ul`、清單項目裡的 div、引用裡的裸文字都整理好。有模板不支援、會被拿掉的格式（例如底線）時，
    校樣上方先講「這個版型不支援：底線。存檔時會拿掉這些格式，字會留著」，按「照樣存」才存——格式不默默消失。
    清單項目裡存不了的標題、引用、分隔線被攤平、或不收的連結被拆掉，也一樣先講。
  - 游標在清單項目裡（就算中間還夾著 `<p>`，Google 文件貼上常見）就是清單情境：清單按鈕亮、H2／H3 停用、「內文」離開清單。
  - 粗體／斜體按鈕亮不亮照游標處**實際的樣式**（iframe 的 `getComputedStyle`）：`<strong>` 裡明講 `font-weight:normal` 的字不亮；
    標題本來就粗，標題裡只看有沒有 `<strong>`。
  - 樣式明講「不粗／不斜」對任何元素都有效（span、連結、清單、段落），外層粗／斜體在那裡切開；Google 文件貼上最外層的
    `<b style="font-weight:normal">` 包整段時內容不會全變粗。
  - 連結包著圖片區塊時，連結移進 figure 包住 img（`<figure><a href><img></a></figure>`），不會消失。
  - **⌘Z**：工具列的指令都用瀏覽器的編輯指令，進復原堆疊。例外兩個直接改 DOM、不進 ⌘Z：拿掉「一段一段的」
    引用（模板或 AI 產生的 `<blockquote><p>…`），以及後面緊接著引用或清單時插分隔線。「取消」仍可整個還原。
- **已取消的稿件**（D-031，P5-T030）：總覽「已結束」點進去，工作區最上面一條「這篇已經取消。內容都還在，恢復之後可以繼續編輯、發布。」，
  右邊一顆「恢復這篇」。恢復不是破壞性操作，不問確認；按下後重新讀取，回到取消前的樣子（取消前已核准的回到「還沒核准」，
  發布面板照常講要重新核准）。取消的確認框講「內容都留著，之後可以在這篇裡恢復」。
- 校樣用 iframe 載入，套模板自己的 `preview.css`，跟介面的 CSS 完全隔離；建議標記的做法見
  [review-proposals.md](review-proposals.md)「畫面」。
- **主區只有一種預設畫面**（D-018）：標著建議的文章。沒有「編輯／對照／成品」三段切換。
  - **對照**是校樣工具列上的切換按鈕，有未結案的校稿提案時寫「對照 AI 提案」、沒有時寫「對照上一版」（照後端實際比對的對象）；對照蓋在校樣上面（校樣不卸載），對照的工具列換成
    「回到文章」。對照是 git diff 式單欄（D-019）：一張紙，最上面一句粗體摘要加上正文以外的欄位改動，
    下面只列改過的段落（左邊色條：改寫橘、新增綠、刪除紅，標籤寫種類），沒變的收成一條灰底的
    「⋯ 第 a–b 段沒變（n 段）⋯　展開」按鈕。規則見 [review-proposals.md](review-proposals.md)「對照畫面長什麼樣」。
    對照中按右欄卡片就留在對照，捲到那一段並框起來（被收起來的話先展開）。編輯中（P5-T010）不能進對照；
    對照中按「改原文」／卡片的「自己改／去原文改」，先回到文章再進編輯。
  - **成品**（乾淨、什麼都不標）只在發布面板打開時出現，就算剛才在對照也一樣：核准前一定要看過
    真正會送出去的樣子。關掉面板回到原本的文章或對照；面板裡按「回去看」一律回到文章。
    規則在 `src/ui/lib/stage-view.ts`（有測試）。
- **配圖卡片**（右欄「圖片」）：封面那條標「封面」。「用 Codex 生圖」生的時候卡片上有轉圈、mm:ss 計時器、
  一句「通常一分鐘左右，生好會先放在卡片上給你看，不會自動上傳」與「停止」——不畫進度條（D-010）。
  候選圖用虛線框、標「尚未上傳」，跟已上傳的圖分開；按鈕「用這張」（強調色，下一步）與「再生一張」。
  按了停止講「已停止」（中性），不是紅色錯誤。已經有別的封面時不覆蓋，卡片上講怎麼換。
  Codex 不能用時按鈕反灰，原因寫在卡片上，不要讓人按了才失敗。
  內文圖卡片多一行「放在『…』那段之後」（錨點原文，P5-T016）；「用這張」／「上傳這張」之後自動放進那段，
  結果寫在卡片上：放好了綠色「已放進正文第 N 段之後」（「換一張」是「已換掉正文裡原本那張」），沒放黃色
  「找不到建議的位置，請自己放：…」或「AI 還在跑，等它跑完再放（圖已經上傳了）」。另一個 Agent 動作在跑時
  「上傳這張／換一張」反灰不給按（跟「用這張」一樣）。
  已上傳（變淡）的卡片上這行結果不變淡。有有效核准時，按之前先講「放進正文會讓目前的核准失效」。
  描述可以直接改（D-025，P5-T025）：Agent 那條的 prompt 區塊右邊、使用者那條「想要：…」右邊各有一顆小的「改」（鉛筆圖示）。
  按了換成文字框（Agent 那條是多行、使用者那條是一行，Enter 存），底下「n／2000」或「n／200」，超過時數字變紅寫「太長了，刪短一點」、
  Agent 那條清空寫「不能是空的」，「存」反灰；一句說明（Agent：「存了之後，『用 Codex 生圖』就照這段畫」；使用者：「存的時候，會用文章裡

## 品質底線

- 對比至少 4.5:1；鍵盤焦點看得見，不要拿掉 focus ring
- 過場 150–300ms；`prefers-reduced-motion` 要遵守
- 圖示用 SVG（Lucide），**不要用 emoji 當圖示**
- 不要只靠顏色傳達狀態，要有文字或符號
- 桌面優先（這是本機工具），但 1024px 不能爆版
- 破壞性操作（取消 job、移除圖片、撤銷核准）要二次確認；恢復已取消的稿件不是破壞性操作，不問

## 文案

- 動詞用主動式，按鈕寫「發布」不寫「送出」
- 同一個動作全程同名：按鈕寫「發布」，成功訊息就寫「已發布」
- 錯誤要說**發生什麼事**與**怎麼修**，不要道歉也不要含糊
- 空狀態是邀請動作，不是裝飾
- 講結果不講判斷：觀察卡片的略過鈕寫「不用改」，不寫「沒問題」（使用者看不出沒問題是指什麼，P5-T001）
